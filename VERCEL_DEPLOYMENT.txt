=====================================
VERCEL DEPLOYMENT GUIDE
=====================================

📋 PREREQUISITES
-----------------
1. GitHub account with your code pushed
2. Vercel account (https://vercel.com)


🚀 DEPLOYMENT STEPS
-------------------

METHOD 1: Via Vercel Dashboard (Easiest)
========================================

1. Go to https://vercel.com and sign in

2. Click "Add New" → "Project"

3. Import your GitHub repository:
   - Select your repository containing this code
   - Click "Import"

4. Configure project:
   - Framework Preset: Other
   - Root Directory: (leave empty)
   - Build Command: (leave empty)
   - Output Directory: (leave empty)
   - Install Command: npm install

5. Click "Deploy"

6. Wait for deployment to complete (~2-3 minutes)

7. Your deployment URL will be shown:
   https://your-project-name.vercel.app


METHOD 2: Via Vercel CLI
========================

1. Install Vercel CLI:
   npm install -g vercel

2. Deploy from project directory:
   vercel

3. Follow prompts:
   - Set project name
   - Link to existing project or create new
   - Confirm project settings

4. Redeploy to production:
   vercel --prod


METHOD 3: Automatic Deployment (Recommended)
=============================================

1. Connect GitHub to Vercel (one-time setup)
   - Go to https://vercel.com/dashboard
   - Click "Settings" → "Git Integrations"
   - Connect your GitHub account

2. The project auto-deploys when you push to main branch:
   git add .
   git commit -m "Deploy to Vercel"
   git push origin main

3. Check deployment status on Vercel dashboard


📡 WEBHOOK CONFIGURATION
-------------------------

After deployment, update Juspay settings:

1. Get your Vercel deployment URL:
   https://your-project-name.vercel.app

2. In Juspay dashboard, set webhook URL:
   https://your-project-name.vercel.app/api/webhooks

3. Test webhook delivery


🧪 TESTING DEPLOYED WEBHOOK
---------------------------

1. Using curl:
   curl -X POST https://your-project-name.vercel.app/api/webhooks \
     -H "Content-Type: application/json" \
     -d '{"event":"payment.success","order_id":"ORD123"}'

2. Check response:
   Expected: 200 OK with {"received":true}

3. View logs in Vercel:
   - Go to Deployments → Function Logs
   - Click "/api/webhooks" to see request logs


📊 MONITORING & LOGS
--------------------

1. View real-time logs:
   - Vercel Dashboard → Your Project → "Functions"
   - Click "api/webhooks" to see logs

2. Monitor errors:
   - Failed requests show 400/500 status
   - Check Vercel logs for error details

3. Performance metrics:
   - Duration of each request
   - Execution time and memory usage


🔄 UPDATING DEPLOYMENT
----------------------

1. Make code changes locally

2. Commit and push:
   git add .
   git commit -m "Update webhook handler"
   git push origin main

3. Vercel auto-deploys when you push

4. Check deployment status on dashboard


🚨 TROUBLESHOOTING
------------------

1. Deployment fails:
   - Check build logs in Vercel dashboard
   - Verify package.json dependencies are correct
   - Ensure all files are committed to git

2. Webhook not receiving:
   - Verify webhook URL is correct
   - Check Vercel function logs for errors

3. 502 Bad Gateway:
   - Function might be timing out
   - Check logs for errors
   - Verify code doesn't have infinite loops

4. Cannot access deployed URL:
   - Wait for deployment to complete (status: Ready)
   - Check if project is public/private access
   - Clear browser cache and try again


📁 PROJECT STRUCTURE FOR VERCEL
-------------------------------

project/
├── api/
│   ├── webhooks.js       ← Webhook handler
│   └── health.js         ← Health check
├── vercel.json           ← Vercel config
├── package.json          ← Dependencies
└── VERCEL_DEPLOYMENT.txt ← This file


💡 BEST PRACTICES
-----------------

1. Test webhooks before going live
2. Monitor logs regularly
3. Use custom domain (optional):
   - Add domain in Vercel Settings
   - Update DNS records
   - Juspay webhook URL: https://your-domain.com/api/webhooks

4. Version control:
   - Push all code to git
   - Use main branch for production
   - Tag releases for easy rollback
